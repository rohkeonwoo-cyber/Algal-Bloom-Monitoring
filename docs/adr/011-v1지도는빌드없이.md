# ADR-011 · v1 지도는 빌드 없는 정적 페이지로 만들고, React 도입은 미룬다

- 상태: 채택
- 날짜: 2026-09-16

## 맥락

전국 68개 지점을 지도에 올려야 하는데, 기존 대시보드의 지도는 낙동강 종단 SVG라 전국 좌표를
찍을 수 없다. 새 지도 화면이 필요했다.

앞서 ADR-010 에서 "React 를 쓰되 지도 인스턴스는 렌더 사이클 바깥에서 관리한다"고 정했다.
다만 지금 시점의 조건은 다음과 같다.

- 배포처가 GitHub Pages 다(ADR-005 의 정적 우선). **빌드 산출물을 올리려면 빌드 파이프라인이
  먼저 필요하다.**
- 이 화면의 상태는 단순하다 — 선택된 지점 하나, 필터 세 개. 프레임워크가 해결해 줄 복잡성이
  아직 없다.
- 반대로 **읽을 수 있는 코드**는 지금 당장 필요하다. 기존 `index.html` 은 6.7 MB 단일 파일이라
  저장소를 열어도 코드를 볼 수 없다.

## 결정

`map/` 을 **빌드 도구 없는 정적 페이지**로 만든다.

- `index.html` · `style.css` · `app.js` 세 파일로 나눈다(약 200줄).
- MapLibre GL 은 cdnjs 에서 버전을 고정해 불러온다(5.6.0).
- 배경지도는 브이월드 WMTS 래스터. 타일 주소가 `{z}/{y}/{x}` 순서인 점을 코드에 적어 둔다 —
  `{z}/{x}/{y}` 로 넣으면 빈 타일(XML 오류)이 온다.
- 데이터는 실행 시 `../data/algae_latest.json` 을 받는다. 파일에 심지 않는다.

**React 는 다음 화면에서 도입한다.** 분석 기능 UI(장면 검색·필터·시계열)가 붙어 상태가
얽히기 시작하는 시점이 적기다. 그때는 빌드 파이프라인도 함께 만든다.

## 검토했으나 버린 안

**지금 React + Vite + Actions 배포까지 한 번에.** 프론트 프레임워크·번들러·CI 배포를 동시에
세우는 일이라 첫 화면이 나오는 시점이 크게 늦어진다. 지금 필요한 것은 68개 지점이 지도에 뜨는
것이다.

**기존 index.html 에 지도를 끼워 넣기.** 6.7 MB 단일 파일을 더 키우는 방향이라 채택하지 않았다.

## 결과

**좋아지는 것**
- 저장소에 올리면 바로 뜬다. 배포 경로가 단순하다.
- 코드가 파일로 나뉘어 읽힌다.

**나빠지는 것**
- 프레임워크 사용 경험이 이 화면에서는 남지 않는다. 목표 직무가 React 를 요구하므로
  **다음 화면에서 반드시 채워야 하는 항목**이다.
- 모듈 번들링이 없어 의존성이 늘어나면 관리가 어려워진다.

## 재검토 조건

- 화면 간 공유 상태가 생기거나(여러 화면이 같은 필터·시간축을 공유), 컴포넌트 재사용이
  필요해질 때 → React 로 옮긴다.
- 정적 배포를 벗어나 서버를 두게 될 때(ADR-005 재검토와 함께).
