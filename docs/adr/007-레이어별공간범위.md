# ADR-007 · 레이어마다 공간 범위를 다르게 가져간다

- 상태: 채택
- 날짜: 2026-09-16

## 맥락

"4대강 전체로 갈 것인가, 낙동강부터 갈 것인가"를 서비스 전체에 대해 하나로 정하려 했으나,
레이어마다 확장 비용이 전혀 다르다는 것이 확인되었다.

**조류경보제 API 직접 조회 결과** (국립환경과학원, 2026-09-16)

지점 코드를 지정하지 않고 요청하면 전국이 반환된다.

| 항목 | 값 |
|---|---|
| 2026년 기록 | 2,562건 |
| 고유 지점 | **68개** |
| 수역 | **40개** (호소 1,419건 / 하천 1,143건) |
| 포함된 보 | 강천·여주·이포·상주·낙단·구미·칠곡·강정고령·달성·합천창녕·창녕함안·세종·공주·백제·승촌·죽산 (16개) |

현재 `scripts/fetch_algae.py`는 4개 지점(강정고령·칠서·물금매리·해평)만 하드코딩해 쓰고 있다.
수위·강수도 전국 자료를 받아 낙동강 유역만 필터링하는 구조다(`scripts/fetch_hrfco.py`).

| 레이어 | 4대강 확장 비용 |
|---|---|
| 조류경보 단계·실측 | **거의 0** (필터만 풀면 됨) |
| 수위·강수 | **거의 0** (동일) |
| 위성 상대강도 | **강마다 재구축** — 중심선·종단구간·수체마스크·보 위치·다년 기준선이 모두 낙동강 전용 |

## 결정

**레이어별로 범위를 다르게 한다.**

```
전국   ├── 조류경보 단계 + 실측값 + 수위·강수      (68개 지점)
       │
낙동강 └── 위성 상대강도 + 경과일 + 이상탐지        (본류)
```

- 첫 화면은 전국 지도에 경보 지점을 띄운다.
- 낙동강으로 확대하면 위성 레이어가 켜진다.
- 다른 강에서는 **"위성 분석 제공 구간: 낙동강 본류"**를 명시한다. 없는 것을 감추지 않는다.

**완성도를 범위보다 우선한다.** 목표 직무 요구사항 중 범위를 넓혀야 채워지는 항목은 없고,
성능·장애 대응·API 설계·분석 UI는 한 대상을 깊게 파야 나온다.

**단계**

| 버전 | 범위 |
|---|---|
| v1 | 낙동강 경보·실측 + 상세 패널 + 장면 검색 (Phase 0와 무관하게 배포 가능) |
| v1.5 | 전국 68개 지점으로 확대 (필터 해제) |
| v2 | 낙동강 위성 상대강도 + 경과일 + 슬라이더 |
| v3 | 이상탐지 레이어 (기준선 산출 후) |
| v4 | 타 수계 위성 확장 (v3 안정 후에만) |

## 검토했으나 버린 안

**전부 낙동강으로 통일.** 설명은 깔끔하지만, 비용 없이 얻을 수 있는 전국 커버리지를 버린다.

**처음부터 4대강 위성 분석.** 강마다 중심선·수체마스크·기준선을 새로 만들어야 한다.
낙동강 하나에 석사연구에서 수 개월이 걸린 작업이며, 완성도가 분산된다.

## 결과

**좋아지는 것**
- 비용 없이 전국 커버리지를 얻으면서 한 유역의 깊이를 유지한다.
- "확장 가능한 구조"를 말이 아니라 동작하는 형태로 보여준다.

**나빠지는 것**
- 지역에 따라 기능이 다르므로 UI가 이를 분명히 알려야 한다. 설명하지 않으면 결함으로 보인다.
- 범위가 다른 레이어를 한 화면에서 다루는 상태 관리가 필요하다.

## 재검토 조건

- 타 수계의 중심선·수체마스크를 확보하거나 생성할 여력이 생길 때.
- 사용자 요구가 특정 수계에 집중될 때.
