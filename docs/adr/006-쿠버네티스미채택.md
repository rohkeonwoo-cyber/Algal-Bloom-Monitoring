# ADR-006 · Kubernetes를 채택하지 않는다

- 상태: 채택
- 날짜: 2026-09-16

## 맥락

목표 직무의 우대사항에 "Docker·Kubernetes"가 명시되어 있다. 그러나 이 서비스의 실제 조건은
다음과 같다.

- 단일 노드(ARM 2 OCPU / 12 GB, ADR-005)에 컨테이너 3~4개.
- 공개 트래픽 규모가 작고, 급격한 부하 변동이 예상되지 않는다.
- 배치는 정해진 시각 또는 신규 장면 도착 시 실행된다(ADR-002).

Kubernetes의 존재 이유는 오토스케일링, 무중단 롤링 배포, 다중 노드 스케줄링이다.
위 조건에는 해당 사항이 없다.

## 결정

**Docker Compose로 구성한다.** Kubernetes(관리형·k3s 모두)를 도입하지 않는다.

대신 이 문서를 남겨, 검토한 뒤 의도적으로 채택하지 않았음을 기록한다.

운영에 필요한 최소한은 다음으로 대체한다.

| 필요 | 대체 수단 |
|---|---|
| 재시작·자동 기동 | Compose restart 정책 + 부팅 시 자동 실행 |
| 실행 이력·실패 로그 | systemd timer + journald (cron은 실패해도 조용하다) |
| 헬스체크 | 컨테이너 헬스체크 + 외부 상태 배지 |
| 배포 | 이미지 태그 교체 + Compose 재기동 |

## 검토했으나 버린 안

**k3s(경량 Kubernetes) 도입.** 우대사항에 직접 대응되지만, 트래픽이 없는 단일 노드에서
"왜 썼는가"에 답하기 어렵다. **"우대사항이라서"는 설계 근거가 아니다.**

**관리형 Kubernetes.** 컨트롤 플레인 요금이 별도로 붙어 비용 0 제약(ADR-005)에 어긋난다.

## 결과

**좋아지는 것**
- 구성이 단순해 운영 부담과 장애 표면이 작다.
- 기술을 고른 근거뿐 아니라 **고르지 않은 근거**가 문서로 남는다.

**나빠지는 것**
- Kubernetes 실무 경험은 이 프로젝트로 얻지 못한다.
- 우대사항 한 줄을 비워 둔다. 이 문서가 그 자리를 대신하는 답변이 된다.

## 재검토 조건

- 노드가 둘 이상 필요해질 때(무중단 배포 요구, 지역 분산, 부하 분리).
- 배치 워크로드가 늘어 스케줄링·재시도 관리가 Compose로 감당되지 않을 때.
- 서비스가 안정된 뒤 **학습 목적**으로 옮길 경우, 서비스의 필수 경로가 아닌 별도 과제로 둔다.
