# ADR-008 · 관측 데이터를 코드 저장소 밖으로 옮긴다

- 상태: 채택
- 날짜: 2026-09-16

## 맥락

현재 수집 파이프라인은 매시간 공공 API를 조회해 결과 JSON을 Git에 커밋하고 GitHub Pages로
서빙한다. 정적 호스팅만 가능한 조건에서는 합리적인 선택이었다.

그 결과 저장소 이력이 다음과 같아졌다(2026-09-16 기준).

| 항목 | 값 |
|---|---|
| 총 커밋 | 140개 |
| 데이터 갱신 커밋 | **119개 (85%)** |
| 사람이 작성한 커밋 | 21개 |

저장소를 열면 `chore: 실시간 데이터 갱신`이 화면을 채우고, 의미 있는 21개 커밋이 묻힌다.
또한 시계열이 쌓일수록 저장소가 계속 커진다.

ADR-005에서 상시 실행 서버와 오브젝트 스토리지를 확보하기로 하면서, 정적 호스팅이라는
원래의 제약이 사라졌다.

## 결정

**관측 데이터를 Git에서 분리한다.**

| 데이터 | 이동 위치 |
|---|---|
| 지점 관측값·경보 단계 시계열 | PostGIS |
| 위성 산출물(COG), 기준선 | 오브젝트 스토리지 |
| 코드·설정·문서 | Git (그대로) |

커밋 이력에는 사람이 내린 변경만 남는다.

**Git 운영 방식도 함께 정한다.**

- 기능 단위 브랜치 + PR. PR 본문에 판단 근거를 적어 설계 기록으로 삼는다.
- 태그와 릴리스 노트를 ADR-007의 버전 단계(v1, v1.5, v2 …)에 맞춘다.
- GitHub Actions는 **테스트·린트**에 쓴다. 공공 API 수집은 Actions에서 하지 않는다
  (`api.hrfco.go.kr` 접근 실패 전례가 있고, 원인은 확인되지 않았다 — 아래 참조).

## 검토했으나 버린 안

**데이터 전용 브랜치(orphan branch)로 분리.** 저장소 하나로 유지되지만 여전히 Git이 시계열
데이터를 담고, 저장소 크기 문제는 남는다.

**데이터 전용 저장소를 따로 두기.** 정적 호스팅을 유지해야 할 때의 차선책. 서버를 확보하면
불필요하다.

## 기록해 둘 사실

GitHub Actions에서 `api.hrfco.go.kr` 접근에 실패해 수집을 로컬로 옮긴 경위가 있다.
이후 조사에서 **"한국 공공 오픈 API가 해외 IP를 차단한다"는 공식 근거는 확인되지 않았다.**
따라서 정확한 진술은 다음과 같다.

> `api.hrfco.go.kr`은 GitHub Actions 환경에서 접근에 실패했다. 원인이 국가 단위 차단인지,
> 러너 IP 대역 문제인지, 다른 이유인지는 **확인되지 않았다.**

ADR-005의 배포처가 국내 리전이므로 이 문제는 실무상 발생하지 않는다.

## 결과

**좋아지는 것**
- 커밋 이력이 사람의 판단 기록이 된다.
- 저장소가 무한히 커지지 않는다.
- 시계열 질의를 SQL로 할 수 있어 검색·필터·집계가 쉬워진다.

**나빠지는 것**
- DB 백업과 복구 절차가 필요해진다. Git이 대신해 주던 이력 관리를 직접 해야 한다.
- 서버가 없으면 데이터도 없다. 정적 호스팅의 무장애 특성을 잃는다.

## 재검토 조건

- 서버 운영을 중단하고 정적 구성으로 되돌아갈 때(ADR-005의 최후 폴백).
